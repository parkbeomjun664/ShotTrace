# 일정 — 11월 완성 · 12월 여유 · 1~2월 공부와 개선

> 2026-09-09 재수립. 12/31 완성 → **11/26 완성**으로 5주 당겼다.
> 하루 분량이 얇아 이틀치를 20분에 끝내는 일이 반복됐다.
> 12월은 밀렸을 때의 흡수 구간이자, 안 밀리면 개선 기간이다.

## 원칙

### 하루 할당량

**하루 3시간.** 실작업은 **월~목 4일**, 금요일은 마감·예비. 토·일은 쉰다.

| 요일 | |
|---|---|
| 월~목 | 그 주의 작업. **하루에 산출물 하나** |
| 금 | 마감·예비 — ADR · 배포 확인 · 밀린 것 |
| 토·일 | 쉰다 |

**하루의 끝에 남아야 하는 것**

1. 커밋 **1개 이상**
2. 필기 **1장**
3. `docs/오늘.md` 에 **"내일 할 것" 한 줄**

### 하루 분량을 어떻게 잡나 — 2026-09-09 개정

이전에는 "한 주제 = 하루"로 잡았다. 그게 얇았다.
이제 **"하루 = 눈에 보이는 산출물 하나"** 로 잡는다.

```
얇았던 예    "Recharts 기초 — 막대 하나 그려보기"
새 기준      "품질 화면에 파레토 차트가 뜬다"
```

읽기·복습은 작업이 아니라 준비다. 하루의 앞 20분에 넣고 분량에서 빼지 않는다.

### ⚠️ 표시

**처음 하는 일이거나 정답이 없는 설계**다. 3시간에 안 끝날 수 있다.
3시간이 되면 **멈추고 어디까지 갔는지 기록한 뒤 금요일 예비를 쓴다.**
이어서 4시간, 5시간 하지 않는다.

### 밀렸을 때

기능을 줄이지 일정을 밀지 않는다. [기능 등급](#기능-등급)과
[자르는 순서](#자르는-순서)에 미리 정해뒀다.
12월이 통째로 비어 있으므로 **한 달치까지는 흡수된다.**

### 재계획 지점 — **10/9 (금)**

시간의 설계(S04)에 들어가기 직전이다. 여기서 한 번 멈추고 남은 7주를 다시 본다.
이전 계획은 11/1이었으나, 압축했으므로 **더 일찍 점검**한다.

- S01~S03이 계획대로 왔는가 (화면 · 파이프라인 앞단)
- 새 견적이 또 헐렁하면 한 번 더 당긴다
- 빡빡하면 자르는 순서에서 몇 번까지 자를지 정한다

매주 흔들지 않는다. 이 판단은 10/9에 한 번만 한다.
