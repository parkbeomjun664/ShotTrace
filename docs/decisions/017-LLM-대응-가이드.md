- **관련 ADR**: [012](012-실시간-갱신.md) · [013](013-인증과-인가.md) · [014](014-취소와-정정.md)

## 무엇을 정했나

| 질문 | 결정 |
|---|---|
| 무엇을 만드나 | 불량이 난 **끝난 LOT** 의 의심 원인 · 점검할 곳 (최대 3개) — **참고용, 판단은 사람이** |
| Claude 에게 무엇을 주나 | 서버가 고른 **그 LOT 의 숫자만** — 변수별 양품/불량 평균 · 표준편차 · z, 불량 사유 · 위치(몇 번째 샷 · 몇 분), 겹친 비가동 |
| 답의 모양 | **구조화 출력** (`GuideSchema`) — 근거는 `metric` 하나, **목록(`z.enum`) 중에서만** |
| 화면의 숫자 | Claude 의 답이 아니라 **이 LOT 의 샷에서 우리가 센 값** (`metricStats`) |
| 키 | **서버에만** — `server-only` · `NEXT_PUBLIC_` 없음 |
| 누가 누르나 | **worker · admin** — 부르기 **전에** 역할 확인, 저장은 RLS 가 한 번 더 |
| 다시 부르나 | 안 부른다 — `lot_guide`(PK = lot_id)에 저장하고 다시 보여준다. 고치지 않는다(장부와 같다) |
| 모델 | `claude-opus-5-5` · effort medium · 거절되면 서버 대체 모델(`fallbacks: "default"`) · 실제로 답한 모델을 저장 |

## 왜

### ① LLM 은 "그럴듯하게 틀리는" 대표 선수다 — 오픈북으로 바꾼다

질문만 보내면 사출성형 일반 상식으로 답을 지어낸다. 에러 없이 틀리는 것 — 이 프로젝트가 가장 피해 온 것이다.
그래서 질문과 함께 **우리 숫자**를 보내고, 원인 판단은 그 안에서만 하게 했다. 근거가 약하면(|z| < 1) 단정하지 않고,
판단할 수 없으면 `causes` 를 비운다. 불량 1개짜리 LOT 에서 실제로 비웠다 — "이것만으로는 원인을 판단할 수 없습니다".

### ② 숫자는 Claude 가 옮겨 적지 않는다 — ADR 012 와 같은 생각

근거 숫자를 Claude 에게 적게 하면 옮겨 적다 틀릴 수 있다. 그래서 **근거의 이름만** 받고(목록에 없는 이름은 스키마가
거절한다 — 테스트로 확인), 화면은 그 이름으로 우리가 센 숫자를 붙인다. Realtime 알림이 와도 **알림의 값을 쓰지 않고
DB 를 다시 읽는** ADR 012 와 같다 — **남이 건넨 숫자보다 내 DB.**

### ③ 데이터가 모자라면 Claude 가 사람에게 일을 넘긴다 — 그 자리가 다음에 줄 데이터다

첫 버전의 오픈북에는 불량이 LOT 의 **어디서** 났는지가 없었다. Claude 는 "불량 샷이 LOT 시작 직후에 몰려 있는지
**샷 순번으로 확인하세요**" 라고 썼다 — 우리 DB 에 답이 있는 질문이다. 불량 위치(`defect_positions`)를 넣자
"LOT 초반 연속된 샷에 몰려 있습니다" 라고 **직접** 판단했다. 입력은 355 토큰(약 2원) 늘었다.

### ④ 판단은 데이터로, 점검 제안은 상식도 — 둘을 나눈다

"JSON 에 있는 것만" 을 전부에 걸면 점검 제안이 쓸모없어진다 — "벤트를 보라" 는 원래 현장 상식이다.
그래서 **원인 판단**(summary · title · reasoning)은 데이터로만, **점검할 곳**(check)은 상식을 쓰되 데이터로 확인된 것처럼
쓰지 않게 했다. 고친 뒤 점검 칸은 모두 "~인지 확인하세요" 로 나왔다.

### ⑤ 돈이 드는 버튼 — 막는 곳은 둘, 순서가 중요하다

RLS 는 **저장할 때** 막는다. 그때는 이미 Claude 를 부른 뒤다. 그래서 Server Action 이 **부르기 전에** 역할을 확인하고,
RLS 는 그 뒤의 마지막 문이다. viewer 비밀번호는 README 에 공개돼 있다 — 아무나 우리 돈을 쓰면 안 된다.
크레딧은 선불 $5 · 자동 충전 끔 — 키가 새도 잃는 것은 잔액까지다. 그래서 키 만료는 두지 않았다.

### ⑥ 비용 — 한 번에 약 25 ~ 40원

| LOT | 입력 | 출력 | 약 |
|---|---|---|---|
| 불량 1 (판단 불가) | 1,541 | 568 | $0.018 |
| 불량 5 · 위치 없음 | 1,547 | 848 | $0.023 |
| 불량 5 · 위치 있음 | 1,902 | 1,028 | $0.028 |

출력이 입력의 절반인데 비용은 두 배 넘는다 — 출력 단가가 5배다(생각도 출력이다). 누를 때만 부르고, 저장해서 다시 쓴다.

## 버린 대안

**① 페이지를 열 때 자동으로 만들기** — 누를 필요가 없다. 버린 이유 — 열 때마다 돈이 나가고, 진행 중 LOT 은 데이터가 아직 다 안 왔다.

**② 숫자까지 Claude 가 쓰게 하기** — 문장이 자연스럽다. 버린 이유 — 옮겨 적다 틀려도 에러가 안 난다. 화면이 붙인다.

**③ DB 를 Claude 에게 도구로 주기 (tool use · 에이전트)** — 스스로 필요한 것을 찾는다. 버린 이유 — 무엇을 읽었는지
통제하기 어렵고 호출이 여러 번이라 비싸다. 이 일은 **표 하나 읽기** — 호출 한 번이면 된다.

**④ 다시 만들기 버튼 (UPDATE)** — 프롬프트를 바꾸면 새 답을 볼 수 있다. 버린 이유 — 가이드도 기록이다. 장부처럼
고치지 않는다. 테스트로 만든 것은 SQL Editor 에서 지웠다(화면에는 DELETE 정책이 없다).

**⑤ 더 싼 모델** — 비용이 줄어든다. 보류 — 지금도 한 번에 수십 원이고 누르는 횟수가 적다. 쓰임이 늘면 다시 잰다.

## 🔴 따라오는 것

- **LLM 에게는 "모르면 모른다" 의 출구를 준다** — 빈 `causes` 가 정답일 때가 있다
- **LLM 의 답에서 숫자를 믿지 않는다** — 이름(enum)을 받고 숫자는 내가 붙인다
- **돈이 드는 일은 돈이 나가기 전에 막는다** — RLS 는 마지막 문
- **LLM 이 꺼져도 앱은 멀쩡하게** — 키 없음 · 잔액 0 · 네트워크는 이 버튼만 "지금은 만들 수 없어요"
- **테스트는 빨간불을 본다** — 순번 테스트가 처음엔 정렬을 빼도 통과했다(데이터가 우연히 같은 답)
