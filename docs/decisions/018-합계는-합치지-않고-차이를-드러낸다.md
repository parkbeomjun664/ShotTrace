# 018. 두 화면의 합계는 합치지 않고, 차이를 드러낸다

- **상태**: 채택
- **날짜**: 2026-10-26
- **관련 파일**: `db/migrations/024_part_without_lot.sql` · `apps/web/app/page.tsx` · `apps/web/app/quality/page.tsx`
  · `apps/web/e2e/totals.e2e.ts` · `scripts/demo/demo_lot.sql` · `scripts/demo/fix_20261007_rh.sql`
- **관련 ADR**: [005](005-샷과-부품-분리.md) · [006](006-LOT-경계.md) · [008](008-집계-위치.md) · [012](012-실시간-갱신.md)

## 무엇을 정했나

현황판의 생산 수(5,314)와 품질 화면의 전체 수(5,313)가 다르다. **둘을 하나로 맞추지 않는다.**
각 화면이 무엇을 세는지 그대로 두고, 차이 = **어느 LOT 에도 안 든 부품 수**를 View(`part_without_lot`)로 세어
화면에 드러낸다. 그리고 E2E 가 매번 **현황판 = 품질 + LOT 밖 부품** 인지 확인한다.

## 왜

두 숫자는 서로 다른 질문에 대한 답이다.

| 화면 | 세는 것 | 질문 |
|---|---|---|
| 현황판 | `shot_part` 부품을 직접 (ADR 012) | 설비가 지금까지 몇 개 찍었나 — LOT 을 안 열었어도 |
| 품질 | LOT 에 묶인 수량의 합 | LOT 단위로 추적되는 생산 중 불량이 얼마인가 |

처음 차이는 **43개**였다. 원인은 데모 스크립트가 패밀리 금형(ADR 005)의 **LH LOT 만 열고 RH LOT 은 안 연 것** —
RH 42개 + 경계 밖 1개. RH LOT 을 열어 고치고(`fix_20261007_rh.sql`) 스크립트도 둘을 함께 열게 바꿨다.
남은 1개도 진짜 "LOT 밖 부품"이다.

이 사건이 결정의 근거다. **차이가 있었기 때문에 데모 스크립트의 버그를 찾았다.** 숫자를 하나로 합쳤다면
42개 부품은 조용히 사라졌거나(품질 기준) 출처 없이 섞였을 것이다(현황판 기준).
0 이 아닌 LOT 밖 부품은 "LOT 을 안 열었거나 경계가 틀렸다"는 **신호**다 — 숨기면 신호가 꺼진다.

## 버린 대안

**① 한 View 로 합쳐 두 화면이 같은 숫자를 보게** — 사람이 헷갈리지 않는다. 버린 이유 — 어느 쪽으로 합쳐도 한쪽이 거짓이 된다.
LOT 기준이면 현황판이 LOT 을 안 연 생산을 못 본다(실시간 시연에서 숫자가 안 오른다).
부품 기준이면 품질 화면이 LOT 으로 추적되지 않는 부품까지 "LOT 품질"로 센다.

**② 차이를 숨기고 각자 숫자만** — 화면이 깔끔하다. 버린 이유 — 처음 보는 사람이 두 화면을 오가면 "어느 게 맞냐"를 묻는다.
설명할 수 없는 차이는 시스템 전체의 신뢰를 깎는다. 오늘의 43개를 찾은 것도 차이가 눈에 보였기 때문이다.

**③ 품질 화면도 부품을 직접 세기** — 숫자가 같아진다. 버린 이유 — 품질은 "그 LOT 을 만들 때"를 보는 화면이다(ADR 001).
LOT 에 안 묶인 부품은 그때의 설비 상태와 이을 수 없어서 품질 추적의 대상이 아니다.

## 🔴 따라오는 것

- **차이는 화면에 숫자로** — 현황판 "LOT에 안 묶인 부품 N개 포함", 품질 ⓘ "LOT 없는 부품 N개는 현황판에만"
- **E2E 로 묶는다** — `totals.e2e.ts` 가 현황판 = 품질 + LOT 밖 부품을 확인한다. 셋 중 하나가 바뀌면 깨진다
- **패밀리 금형의 LOT 은 LH · RH 를 같이 연다** — `demo_lot.sql`
