# 006. LOT 경계 — `ended_at = 마지막 샷 + 1초`, 조회는 반열린 구간

- **상태**: 채택
- **날짜**: 2026-09-02

## 무엇을 정했나

LOT 은 `EQUIP_CD + PLAN_DATE + PART_NAME` 조합으로 정의하고, 시간 경계를 이렇게 잡는다.

```
started_at = 그 LOT 첫 샷의 measured_at
ended_at   = 그 LOT 마지막 샷의 measured_at + 1초
```

조회는 항상 **반열린 구간**으로 한다.

```sql
measured_at >= started_at AND measured_at < ended_at
```

`lot_id` 는 세 요소를 그대로 담은 문자열로 만든다: `S14-20201016-CN7LH`
(설비 - 계획일 - 차종·방향). 차종+방향 조합은 제품 6개를 고유하게 구분한다.

## 왜

**`ended_at` 에 +1초를 더하는 이유** — 마지막 샷을 잃지 않기 위해서다.
`ended_at` 을 `MAX(measured_at)` 그대로 두면 `measured_at < ended_at` 이
마지막 샷을 **정확히 하나 빼먹는다.** 25개 LOT 이니 매번 25건이 조용히 사라진다.

`001_init.sql` 의 `CHECK (ended_at > started_at)` 도 이걸 요구한다.
샷이 1건뿐인 LOT 이 실제로 2개 있고(S01·S12), 거기서는 `MAX = MIN` 이라
+1초가 없으면 **제약 위반으로 적재가 실패한다.**

**반열린 구간을 쓰는 이유** — 구간을 이어붙일 때 경계가 겹치지 않는다.

```
LOT A  [10:00, 10:30)
LOT B  [10:30, 11:00)      ← 10:30 샷은 B 에만 속한다
```

`BETWEEN` 은 양끝을 포함하므로 경계 시각의 샷이 **두 LOT 에 동시에 잡힌다.**
같은 설비에서 LOT 이 연달아 돌면 반드시 터진다.

또한 `>=` 와 `<` 는 `(equipment_id, measured_at)` 인덱스를 **범위 스캔**으로
그대로 쓸 수 있다. 왼쪽 접두사 규칙.

## 버린 대안

- **`BETWEEN started_at AND ended_at`** — 읽기는 쉽다. 하지만 양끝 포함이라
  경계 샷이 두 LOT 에 중복으로 잡힌다. 커리큘럼 초안에 `BETWEEN` 으로 적혀 있었고
  이 결정으로 정정했다.

- **`ended_at` 을 계획 종료시각(예: 그날 자정)으로** — LOT 이 실제로 언제 끝났는지를
  잃는다. 설비 유휴 시간까지 LOT 구간에 들어가 **가용률 계산이 틀린다** (OEE).

- **`ended_at` 없이 다음 LOT 의 `started_at` 을 경계로** — 마지막 LOT 의 끝을
  정의할 수 없고, LOT 하나를 조회할 때마다 이웃 LOT 을 함께 읽어야 한다.
  조회가 자기 완결적이지 않다.

- **`equipment_param` 에 `lot_id` FK 를 넣기** — [ADR 001](001-시간구간-조인-구조.md)
  에서 이미 버렸다. 시간 구간 조인이 이 프로젝트의 정체성이다.
