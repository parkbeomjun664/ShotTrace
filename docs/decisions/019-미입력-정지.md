# 019. 미입력 정지 — 찾아서 보여주고, 사유는 사람이 고른다

- **상태**: 채택
- **날짜**: 2026-10-26
- **관련 모듈**: M23 · M24 · M28
- **관련 파일**: `db/migrations/026_unrecorded_stop.sql` · `apps/web/app/downtime/page.tsx` · `apps/web/app/downtime/StopList.tsx`
  · `apps/web/app/downtime/actions.ts` (`confirmStops`) · `apps/web/lib/downtime.ts` · `apps/web/lib/oee.ts` (`withStops`)
- **관련 ADR**: [006](006-LOT-경계.md) · [015](015-데이터-모델링.md) · [016](016-OEE.md)

## 무엇을 정했나

비가동 기록이 비어 있어 가동률이 전부 100% 다(ADR 016 ⑥). LOT 안에서 **샷 사이가 표준 CT × 5 를 넘은 빈 곳**을
View(`unrecorded_stop`)로 찾아 비가동 화면에 **"사유 미입력 정지"** 목록과 타임라인 빗금으로 보여준다.
사람이 사유를 고르면(여러 개 한꺼번에) 그때 `downtime` 에 `source = 'inferred'` 로 기록되고,
OEE View 가 시간 구간 조인으로 알아서 가동률에 넣는다.

규칙 — ① LOT 구간 안만(LOT 사이의 밤 · 주말은 계획된 생산 시간이 아니다) · ② 표준 CT × 5 초과 ·
③ 정지 = [앞 샷 + 표준 CT, 뒤 샷) · ④ 패밀리 금형의 LH · RH 중복은 하나로 · ⑤ 이미 기록된 비가동과 겹치면 뺀다.
240분 이상은 **계획 정지 후보**로 따로 묶는다(교대 · 휴식 · 점검일 가능성).

## 왜

ADR 016 은 샷 틈을 자동으로 비가동에 넣는 것을 버렸다 — **사유가 없고 기준이 없다.** 그 판단은 그대로다.
바뀐 것은 "자동으로 넣기"가 아니라 **"찾아서 보여주기"** 라는 점이다.

- **추정하지 않는다** — 화면은 "여기 빈 곳이 있다"까지만 말한다. 비가동이 되는 순간은 사람이 사유를 고를 때다.
  현장 MES 도 설비 신호로 정지를 잡고 사유는 작업자가 단다
- **OEE 는 그대로다** — 멈춘 시간은 이미 성능 손실에 들어가 있다. 사유를 고르면 그 시간이 성능 → 가동률 손실로
  **옮겨 갈 뿐** 곱한 값은 같다. 숫자를 바꾸는 기능이 아니라 손실이 **맞는 칸에 가게** 하는 기능이다
- **기록하기 전에 효과를 보여준다** — "모두 기록하면 가동률 약 N% (지금 M%)" (`withStops`, 순수함수 · 테스트)
- **두 번 기록되지 않는다** — 겹치는 비가동은 DB 가 거절하고(23P01) 그 줄은 건너뛴다

## 버린 대안

**① 빈 곳을 자동으로 비가동 기록** — 가동률이 바로 현실적이 된다. 버린 이유 — ADR 016 ⑥ 그대로. 사유 없는 비가동은
OEE 를 바꿔도 **무엇을 고칠지** 알려주지 않는다. 그리고 "5배" 는 우리가 정한 기준이지 사실이 아니다.

**② 보여주기만 하고 기록은 「직접 추가」로** — 기능이 하나 적다. 버린 이유 — 수십 개의 빈 곳을 하나씩 시각을 옮겨 적게 된다.
옮겨 적다 틀린다. 찾은 구간을 그대로 쓰고 사유만 고르게 했다.

**③ LOT 사이(밤 · 주말)도 정지로** — 설비가 논 시간이 다 보인다. 버린 이유 — 계획된 생산 시간이 아니다.
OEE 의 부하는 LOT 단위다(ADR 016 ②). 넣으면 하루 휴무가 거대한 정지가 된다.

**④ 기준을 고정 분(예: 5분)으로** — 단순하다. 버린 이유 — 제품마다 사이클이 다르다. 표준 CT 의 배수가 제품을 따라간다.

## 🔴 따라오는 것

- **화면과 View 가 같은 기준** — `GAP_FACTOR = 5` (`lib/shots.ts`) 와 026 의 `* 5`. 하나만 바꾸면 차트의 빈 칸과 목록이 어긋난다
- **`source` 로 출처를 남긴다** — `manual`(직접 입력) · `inferred`(빈 곳에 사유를 고름). 나중에 기준을 바꿔도 어느 기록이 영향받는지 안다
- **쓰기 전에 역할 확인** — 버튼 잠금은 친절, RLS 가 마지막 문(ADR 013)
