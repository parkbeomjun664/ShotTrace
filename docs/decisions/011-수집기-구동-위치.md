# 011. 수집기는 docker compose 안에서 돈다

- **상태**: 채택
- **날짜**: 2026-10-02
- **관련 모듈**: M17 · M28
- **관련 파일**: `docker-compose.yml` · `services/collector/`
- **관련 ADR**: [009](009-설비-메시지-계약.md) · [010](010-시간의-설계.md)

## 무엇을 정했나

수집기를 `docker-compose.yml` 의 서비스로 올린다. 브로커와 한 묶음이다.

```yaml
services:
  mosquitto:
    ...
  collector:
    build: ./services/collector
    depends_on: [mosquitto]
    env_file: .env                # 🔴 이미지에 굽지 않는다
    restart: unless-stopped
```

구현은 S05 월요일에 붙인다. 오늘은 위치만 정한다.

## 왜

### 수집기는 "항상 켜져 있어야 하는" 프로그램이다

ADR 009 에 적었다 — *"구독자가 없을 때 보낸 메시지는 QoS 와 무관하게 사라진다."*

9/28 에 실제로 겪었다. 시뮬레이터를 먼저 돌리고 수집기를 나중에 켰더니
**적재 0건** 이었고, **에러는 하나도 안 났다.** 세는 코드가 없었으면 몰랐다.

"가끔 켜는 스크립트" 가 아니라 **"꺼지면 데이터를 잃는 프로그램"** 이다.

### 서버리스에는 구조적으로 못 올린다

```
요청-응답형 (Vercel · Supabase Edge Function)   요청이 올 때만 깨어난다
수집기                                          MQTT 연결을 계속 붙들어야 한다
```

S05 에서 붙일 Supabase Realtime 과 정반대다. 거기는 **브라우저가** 연결을
붙들지만, 여기는 **서버 쪽이** 붙들어야 한다.

### 브로커와 수집기는 같이 살고 같이 죽는 짝이다

둘 중 하나만 떠 있으면 아무 의미가 없다. 같은 `compose` 파일에 두면
수명 주기가 자동으로 묶인다.

### 재현 가능해진다

```
docker compose up -d        브로커 + 수집기가 뜬다
replay.py                   시뮬레이터만 손으로 돌린다
```

받아보는 사람이 **명령 하나로 파이프라인 절반을 띄울 수 있다.**
*"제 컴퓨터에선 됩니다"* 가 성립하지 않는다.

### `restart: unless-stopped` 가 "죽으면 다시" 를 맡는다

다만 **Docker 자체가 떠 있을 때의 약속**이다. 9월에 Docker Desktop 이 꺼져
있어 컨테이너가 안 뜨는 일을 네 번 겪었다. **감시자를 누가 감시하느냐**는
윈도우에서는 사람 또는 Docker Desktop 의 자동시작 설정이다.

## 버린 대안

**① 로컬에서 손으로 (지금 방식)**
당장 편하다. 버린 이유 — 끄면 끝이고, 다른 사람이 재현할 수 없다.

**② 클라우드 상시 서버 (Railway · Fly · Render)**
진짜 24시간 돈다. 버린 이유 — **지금은 과하다.** 시뮬레이터도 손으로 켜는데
수집기만 클라우드에 있으면 **둘이 만나지 않는다.** 비용과 계정도 하나 더 는다.
12월 여유에 "항상 살아있는 데모" 를 만들 때 다시 본다.

**③ Supabase Edge Function**
Supabase 안에서 끝난다. 버린 이유 — **구조가 안 맞는다.** 상시 연결을
유지하는 프로그램을 요청-응답 런타임에 올릴 수 없다.

**④ 시뮬레이터도 compose 에 넣기**
전부 한 번에 뜬다. 버린 이유 — 시뮬레이터는 **배속·설비·개수를 바꿔가며
손으로 돌리는 도구**다. 항상 떠 있을 이유가 없고, 터미널에서 로그를 보는 게
목적이다. 그리고 ADR 009 의 "한 프로세스 = 한 설비" 를 compose 로 표현하면
설비마다 서비스를 적어야 한다.

## 🔴 따라오는 것

- **`services/collector/Dockerfile` 이 필요하다.** python:3.12-slim 기반.
- **`.env` 를 이미지에 굽지 않는다.** `env_file:` 은 **실행할 때 넘기는** 방식이다.
  `COPY .env` 를 Dockerfile 에 쓰면 **이미지에 `service_role` 키가 박힌다.**
  이미지를 어디 올리는 순간 RLS 를 통째로 우회하는 키가 공개된다.
- **로그는 `docker compose logs -f collector`** 로 본다. 터미널에 안 뜬다.
- **`.dockerignore`** 로 `.env` · `data/` · `.venv/` 를 빌드 컨텍스트에서 뺀다.
  빌드 컨텍스트에 들어간 파일은 `COPY` 를 안 써도 데몬으로 전송된다.

## 남은 것

- **헬스체크** — 수집기가 살아있는지 compose 가 어떻게 아나. 지금은 프로세스가
  떠 있으면 살아있다고 본다. S09(관측성)에서 다룬다.
- **지속 세션** — compose 로 올려도 컨테이너를 내린 동안의 메시지는 사라진다.
  ADR 009 의 남은 것 그대로다.
