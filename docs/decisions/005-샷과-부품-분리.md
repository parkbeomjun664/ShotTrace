# 005. 패밀리 금형 — 샷과 부품을 두 테이블로 분리

- **상태**: 채택
- **날짜**: 2026-09-02
- **관련 모듈**: M02 · M05 · M06
- **영향**: [ADR 001](001-시간구간-조인-구조.md) 을 보완한다 (대체하지 않는다)

## 무엇을 정했나

001 의 `equipment_param`(부품 1개 = 1행, 5,232행)을 두 테이블로 나눈다.

| 테이블 | 단위 | 행 | 담는 것 |
|---|---|---|---|
| `shot` | 한 번의 사출 | 2,626 | 공정변수 24개 |
| `shot_part` | 그 샷에서 나온 부품 | 5,232 | 제품 · 캐비티 · 양품/불량 |

`shot` 의 PK 는 `(equipment_id, measured_at)` 복합키다. **PK 가 곧 시간 구간 조인 인덱스**가 된다.
`shot_part` 는 `(equipment_id, measured_at)` 복합 FK 로 `shot` 을 가리킨다.

## 왜

**S14 는 패밀리 금형이다.** 한 번의 샷에서 LH · RH 두 부품을 동시에 찍는다.

같은 `(설비, 시각)` 에 행이 2개씩 있고, 그 두 행에서 **공정변수 24개가 전부 같다.**
2,626개 샷 그룹을 전수 검사했다:

```
샷 그룹 2,626개 / 그룹 안에서 값이 갈리는 공정변수: 0개
값이 갈리는 것은 _id · PART_FACT_SERIAL · PART_NAME · PassOrFail · Reason 뿐
```

- 공정변수(온도·압력·시간)는 **샷의 속성**이다. 한 번만 있어야 한다.
- 품질(양품·불량사유)은 **부품의 속성**이다. LH·RH 가 따로 갈린다.

001 은 둘을 한 테이블에 섞었고, 그래서 **공정변수를 두 번 저장**하고 있었다.

### 실제로 깨진 것 — LOT 시간 구간이 겹쳤다

LH LOT 과 RH LOT 이 **같은 시간대를 공유**한다. 설비 안에서 구간 겹침이 **11건**.
`equipment_id + 시간 범위` 만으로 조인하면 정확히 두 배가 잡힌다.

```
S14 LOT(LH) 187 + LOT(RH) 188 = 375
시간 범위 조인 결과 → 375   (187 이 나와야 한다)
조인으로 잡힌 행 합계 10,459 / 실제 5,232
```

이건 버그가 아니라 **현실**이다. 한 샷이 진짜로 두 LOT 에 기여한다.
모델이 현실을 못 담고 있었을 뿐이다.

### 분리 후 조인

```sql
SELECT s.*, sp.pass_or_fail, sp.fail_reason
FROM   production_lot l
JOIN   shot s      ON s.equipment_id = l.equip_cd
                  AND s.measured_at >= l.started_at      -- 반열린 구간 (ADR 006)
                  AND s.measured_at <  l.ended_at
JOIN   shot_part sp ON sp.equipment_id = s.equipment_id
                  AND sp.measured_at  = s.measured_at
                  AND sp.product_id   = l.product_id     -- 이 LOT 의 제품만
```

25개 LOT 전부에서 `total_qty` 와 조인 결과가 일치한다. 불일치 0건.

**시간 구간 조인은 그대로다.** `shot` 에도 `lot_id` 는 없다(ADR 001 유지).
바뀐 것은 조인 뒤에 `shot_part` 로 제품을 한 번 더 좁힌다는 점뿐이다.

## 버린 대안

- **`equipment_param` 에 `product_id` 만 추가** — 조인은 맞아진다. 변경도 가장 작다.
  하지만 **같은 샷의 온도가 두 행에 그대로 남는다.** "왜 같은 샷 온도가 두 번 저장돼
  있나"에 답할 말이 없다. 실시간 파이프라인(M15~M17)에서도 설비가 보내는 것은
  샷 1건인데 행을 2개로 쪼개 넣어야 한다.

- **LOT 정의를 `설비 + 계획일` 로 바꿔 제품을 뺀다** — 구간이 안 겹치고 스키마도
  그대로다. 대신 LOT 이 제품을 못 가리켜 `production_lot → product` FK 가 사라지고,
  **제품별 수율·불량 파레토를 LOT 단위로 못 뽑는다.** MES 에서 LOT 은 보통 제품 단위다.

- **그냥 두고 화면에서 중복 제거** — *조용히 틀리는 것*을 화면 코드에 떠넘기는 선택이다.
  집계 화면 하나 놓치면 수량이 두 배로 나간다. DB 가 강제할 수 있는 것을
  사람의 주의력에 맡기지 않는다 (M02 ⑤).

## 남은 관찰

`PART_FACT_SERIAL` 은 일련번호가 아니라 **금형 캐비티 번호**로 보인다.
제품별로 값이 5개 이하만 반복되고, 같은 샷의 LH·RH 가 항상 인접한 값이다
(예: LH 23 / RH 24). 컬럼명은 원본을 따라 `part_serial` 로 두되 이 관찰을 남긴다.
