# 009. 설비 메시지 계약 — 토픽 · 페이로드 · QoS · 유언

- **상태**: 채택
- **날짜**: 2026-09-27
- **관련 모듈**: M16 · M17
- **관련 파일**: `services/simulator/replay.py` · `docker-compose.yml`

## 무엇을 정했나

설비(또는 시뮬레이터)가 브로커로 보내는 메시지의 모양을 고정한다.
**이 문서가 곧 계약이다.** 한쪽만 바꾸면 깨진다.

### 토픽 두 개

| 토픽 | 내용 | QoS | retain |
|---|---|---|---|
| `shottrace/{equipment_id}/shot` | 사출 1회 | 1 | **끔** |
| `shottrace/{equipment_id}/status` | `online` / `offline` | 1 | **켬** |

수집기는 `shottrace/+/shot` 과 `shottrace/+/status` 를 구독한다.

### 페이로드 — JSON · UTF-8

```json
{
  "equipment_id": "S14",
  "measured_at": "2020-10-16T04:58:48+00:00",
  "values": { "injection_time": 9.60, "cycle_time": 59.58, "... 24개 ...": 0 },
  "parts": [
    { "part_name": "CN7 W/S SIDE MLD'G LH", "pass_or_fail": "Y", "fail_reason": null },
    { "part_name": "CN7 W/S SIDE MLD'G RH", "pass_or_fail": "N", "fail_reason": "가스" }
  ]
}
```

```json
{ "state": "online" }
```

메시지 하나가 약 1,100 B. 1분에 1건이면 설비당 하루 1.6 MB.

### 규칙 다섯

1. **한 프로세스 = 한 설비 = 한 연결 = 한 유언**
2. `measured_at` 은 **UTC + 오프셋 표기**. 타임존 없는 문자열은 보내지 않는다 (ADR 002)
3. `values` 는 공정변수 24개. 키는 원본 컬럼명의 소문자 (ADR 003)
4. `parts` 는 **순서를 보장하지 않는다.** 받는 쪽은 `part_name` 으로 찾는다
5. 빈 값은 키를 빼지 않고 `null` 을 적는다

## 왜

### 토픽 — 구독자가 거르고 싶은 축만 넣는다

설비를 토픽에 넣으면 브로커가 걸러준다. 페이로드에만 있으면 전부 받아서
구독자가 직접 걸러야 한다. **브로커가 공짜로 해줄 일이다.**

반대로 `part_id` 처럼 **가짓수가 무한한 값**은 넣지 않는다. 브로커는 토픽 트리를
메모리에 들고 있어서 메시지마다 새 토픽이 생기면 끝없이 불어난다.

공장·라인 계층(`shottrace/plant1/line1/...`)은 지금 값이 하나뿐이라 **빈 계층**이
된다. 필요해지면 **앞에 붙이면 된다.**

`shot` 과 `status` 를 나눈 덕에 retain 을 한쪽만 켤 수 있다. 한 토픽에
섞였으면 켤 수도 끌 수도 없다.

### QoS 1 — "정확히 한 번"은 프로토콜이 아니라 설계로 얻는다

샷은 한 건만 잃어도 수율이 틀린다. 그렇다고 QoS 2 를 쓰지 않는다.

```
QoS 2   프로토콜이 보장   왕복 4번   브로커가 메시지 상태를 기억
QoS 1   중복이 올 수 있음  왕복 2번   중복은 받는 쪽이 흡수
```

`shot` 의 PK 가 `(equipment_id, measured_at)` 이라 **upsert 하면 두 번 와도
행이 늘지 않는다.** 어차피 재시도·장애복구 때문에 중복은 어디서든 생기므로
받는 쪽을 멱등하게 만드는 편이 싸고 튼튼하다.

### retain — 상태에는 켜고 사건에는 끈다

| | | retain |
|---|---|---|
| 상태 | 지금 살아있나 | 켠다 — **최신 하나가 곧 진실** |
| 사건 | 샷이 나왔다 | 끈다 — **하나하나가 다 의미** |

`status` 에 켜두면 화면이 켜지는 즉시 가동 여부를 표시할 수 있다. 첫 샷을
기다릴 필요가 없다.

`shot` 에 켜면 새 구독자가 **옛날 샷을 방금 온 샷으로 오해한다.**

### 한 프로세스 = 한 설비

MQTT 는 **연결당 유언이 하나**다. 설비 3대를 한 연결로 흉내내면 어느 설비의
유언을 남길지 정할 수 없다.

문제는 유언이 아니라 모델이었다. **실제 공장도 설비 하나가 브로커에 각자 붙는다.**
3대를 돌리려면 프로세스 3개를 띄운다. 진짜 설비로 갈아끼울 때 그대로 맞는다.

### 유언에 시각을 넣지 않는다

유언은 **연결할 때 만들어져** 브로커에 보관되는 메시지다. 거기 시각을 적으면
"죽은 시각"이 아니라 **"연결한 시각"** 이 된다. 거짓말하는 필드는 넣지 않는다.

죽은 시각이 필요하면 **브로커가 유언을 발행한 시각**을 받는 쪽에서 기록한다.

### 숫자 두 개

- `KEEPALIVE = 15` — 기본 60초는 공장에 느리다. 설비가 멈춘 걸 1분 반 뒤에 아는 셈이다.
  프로세스가 죽으면 TCP 가 닫혀 브로커가 즉시 알지만, **랜선이 빠지거나 전원이
  나가면** 닫아줄 사람이 없어서 이 값으로만 판단한다.
- `MAX_GAP = 300` — 원본 데이터에 3.7일짜리 구멍이 있다. 5분 넘게 빈 구간은
  5분으로 친다. **재생 속도만 거짓말하고 `measured_at` 은 원본 그대로다.**

## 버린 대안

**① 토픽에 설비를 안 넣기** (`shottrace/shot`)
구독자가 설비별로 못 거른다. 전부 받아서 직접 걸러야 한다.

**② 토픽에 `part_id` 넣기** (`shottrace/S14/shot/1`)
토픽이 5,232개가 된다. 구독자는 `part_id` 를 미리 알 수 없어 어차피 `#` 로
받는다. **아무 이득 없이 브로커만 괴롭힌다.**

**③ 공장·라인 계층 미리 파기**
항상 같은 값이 들어가는 빈 계층이 둘 생긴다. 모든 코드와 로그가 길어지는데
얻는 게 없다.

**④ QoS 2**
프로토콜이 중복까지 막아준다. 버린 이유 — 왕복이 4배고, 우리는 DB PK 로
중복을 흡수할 수 있다. **막을 수 있는 걸 비싸게 막지 않는다.**

**⑤ MessagePack / Protobuf**
JSON 보다 3~5배 작다. 버린 이유 — **사람이 못 읽는다.** 개발 중에
`mosquitto_sub` 으로 눈으로 검사하는 값어치가 대역폭보다 크다. 지금은 설비당
하루 1.6 MB 라 아낄 것이 없다. 느려지면 그때 바꾼다.

**⑥ 설비 여러 대를 한 연결로**
프로세스 하나로 끝나서 편하다. 버린 이유 — 유언을 하나밖에 못 남기고,
실제 설비 구조와 모양이 다르다.

**⑦ 페이로드에 `product_id` · `lot_id` 넣기**
수집기가 편해진다. 버린 이유 — **설비는 그걸 모른다.** 둘 다 우리 DB가 만든
개념이다. 시뮬레이터가 DB 스키마에 묶이면 진짜 설비로 바꿀 때 안 맞는다.
이름을 번호로 바꾸는 번역은 수집기의 일이다.

## 결과로 따라오는 것 — S04 수집기

- **QoS 1 로 구독해야 한다.** QoS 는 구간별이라 발행이 1이어도 구독이 0이면
  그 구간은 보장되지 않는다.
- **upsert 로 멱등하게 쓴다.** QoS 1 은 중복을 전제한다.
- **`parts` 를 `part_name` 으로 찾는다.** 순서에 의존하면 조용히 틀린다.
- **`product_id` 번역은 수집기가 한다.** `part_name` → `product.product_id`.
- **연결은 비동기다.** `connect()` 가 돌아와도 CONNACK 전이다. 기다리지 않으면
  `shot` 이 `online` 보다 먼저 나가 "죽은 설비가 샷을 보낸" 로그가 된다.
  시뮬레이터에서 실제로 겪었고 `is_connected()` 대기로 고쳤다.

## 남은 것

- **지속 세션(persistent session)** — 지금은 구독자가 없을 때 보낸 메시지가
  그냥 사라진다. QoS 와 무관하다. **수집기가 죽어 있는 동안의 샷은 잃는다.**
  S04 에서 결정한다.
- **인증 · TLS** — `mosquitto.conf` 가 `allow_anonymous true` 다. 로컬 개발용이고
  실제 공장에서는 필수다.
- **이름 규칙의 중복** — `ISO` 와 `META_COLS`/`DEAD_COLS` 가 `load.py` 와 겹친다.
  세 번째가 생기면 공용 모듈로 뺀다.
