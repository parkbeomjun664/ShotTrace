# MVP 점검 — 끝에서 끝까지 살아 움직이는가

- **날짜**: 2026-10-08 (S05 목)
- **관련**: M18 · `scripts/demo/demo_lot.sql` · [ADR 010](../decisions/010-시간의-설계.md) · [ADR 011](../decisions/011-수집기-구동-위치.md)
- **대상**: 로컬 `localhost:3000` · 배포 `https://shot-trace.vercel.app`

## MVP 를 무엇이라고 보았나

> **시뮬레이터를 켜면, 사람이 아무것도 안 눌러도 배포된 화면의 숫자가 움직인다.**

세 조건이다 — ① 파이프라인 전체가 돈다 ② 실시간이다 ③ 로컬이 아니라 배포본이다.

🔵 **점검표를 먼저 적고 시작했다.** 해보고 나서 적으면 "본 것" 만 적게 된다.
7·8번처럼 **안 될 것 같은 항목을 일부러 넣었다.** 성공할 것만 적으면 점검이 아니라 자랑이다.

## 🔴 점검에서 나온 것 — 넷

### ① 품질 화면 안에서 숫자가 어긋난다

```
헤더      불량 60건 / 전체 5,232개          ← production_lot 저장값 (daily_yield)
파레토    36 + 15 + 10 = 61건               ← shot_part 원본 (defect_pareto)
```

같은 화면에서 60 과 61 이 같이 나온다. 10/7 에 LOT 상세에서 고친 것과 **같은 모양**이다.

### ② 일별 수율에 `0.00%`

DB 는 `null`(계산 안 함)을 줬는데 화면이 `?? 0` 으로 **0 으로 바꿔** 보여줬다.
🔴 **"수율 0%" 는 "전부 불량" 으로 읽힌다.** 거짓말이다 → **오늘 `—` 로 고쳤다.**

### ③ LOT 목록의 `NaN%` — 그리고 틀린 주석

```tsx
const rate = (lot.pass_qty / lot.total_qty) * 100;   // total 0 은 CHECK가 막음
```

🔴 **그 가정이 틀렸다.** 실제 제약은 `total_qty >= 0` 과 `pass + fail = total` 뿐이라
**0 을 허용한다.** 진행 중 LOT(수량 0)을 만들고서야 드러났다.
→ 오늘 `—` 로 고치고, 주석에 **왜 틀렸는지**를 남겼다.

🔵 **주석은 사실이 아니라 그때의 믿음을 적어둔 것일 수 있다.**
"제약이 막아줄 것" 이라고 믿고 쓴 코드는 제약을 직접 읽어서 확인해야 한다.

### ④ 하이드레이션 경고 — 화면에는 안 보이던 것

```
In HTML, whitespace text nodes cannot be a child of <tr>.
```

```tsx
<tr key={lot.lot_id} className="...">  {/* key = PK */}
                                     ↑↑ 이 공백이 "글자" 로 들어간다
```

🔴 **화면은 멀쩡해 보이고 콘솔에만 찍힌다.** 점검표에 "로그를 본다" 가 없었으면 못 찾았다.
→ 주석을 `return` 위로 올려 해결.

`production_lot` 의 저장 수량 세 칸을 **아예 없앨지**까지 같이 정하는 것이 맞다.

## 12. 멱등 — 같은 것을 두 번 넣어도 결과가 같다

`--live` 없이(= 원본 `measured_at` 그대로) 5샷을 다시 보냈다.

```
보내기 전   생산 5,314
재전송      5건 · 적재 실패 0
보낸 후     생산 5,314      변화 없음
```

🔵 **조심해서가 아니라 구조로 지켜진다.** 수집기가 중복을 검사하는 코드는 한 줄도 없다.

```
shot        PK (equipment_id, measured_at)
shot_part   PK (equipment_id, measured_at, product_id)
```

🔴 MQTT 는 QoS 1 이라 **중복 수신이 정상 동작**이다(ADR 009). 끊겼다 붙으면 보낸 것을
또 보낸다. 그때 숫자가 두 배가 되지 않는 근거가 이 PK 다.

## 덤 — HTML 을 읽다 같은 실수를 두 군데 더 찾았다

`<tr>` 에서 터진 "태그 뒤의 공백" 이 `<LiveRefresh />` 뒤에도 있었다.

```
"children":[ <LiveRefresh/> , "                        " , <div>현황판</div> ]
```

🔴 **여기는 `<section>` 안이라 공백이 허용돼 경고가 안 났다.** 같은 실수인데
자리에 따라 터지기도 하고 안 터지기도 한다. 둘 다 정리했다.

## 점검표가 한 일

```
화면만 봤다면          1~6 · 9·10 까지. ✅ 만 남는다
표를 먼저 적었다면     7·8 처럼 "안 될 것 같은 것" 이 들어간다
로그까지 봤다면        ④ 하이드레이션 — 화면에는 안 보이던 것
HTML 을 읽었다면       같은 실수 두 군데 더
```

🔵 **발견 네 개 중 셋은 "화면을 보는 것" 만으로는 안 나왔다.**
"잘 되나 보자" 가 아니라 **"무엇을 어떻게 볼지 먼저 정한 것"** 이 차이를 만들었다.
