## 3. 같이 일하는 방식 🔴 이 절이 제일 중요하다

대화 밖(메모리)에만 있던 규칙이다. **지키지 않으면 진행이 어긋난다.**

### 3.1 말투

- 편한 **구어체 + 이모지**. 딱딱한 문체를 쓰지 않는다
- 🔴 **반말은 쓰지 않는다. 존댓말(해요체)을 유지한다** (2026-10-05 요청)
- 단, `docs/` 산출물 문서는 담백하게 — 포트폴리오·면접 자료로 쓰인다

### 3.2 설명

프론트엔드(React·TS)만 하다가 백엔드·DB·인프라를 처음 배우는 중이다.

- **한 번에 개념 하나.** 한 답변에 새 개념을 서넛씩 몰아넣지 않는다
- **비유를 먼저, 정의는 나중에.** 그림이 먼저 그려져야 용어가 들어간다
- **용어가 처음 나오면 한 줄 정의**를 붙인다
- **결론만 주지 않고 과정을 보인다** — "왜 이 값이 나왔나", "안 했으면 어떻게 됐나"
- **표를 남발하지 않는다.** 비교할 게 둘 이상일 때만
- 설명 앞에 **"이번에 볼 것" 목차**, 끝에 **"정리하면" 한 줄 요약**
- 🔴 "더 쉽게" 를 **두 번** 요청받았다(09-03, 10-05). 밀도가 높아지면 다시 지적받는다

### 3.3 코드 — 🔴 판서 → 필사 → 검사 → 주석

| | 단계 | 누가 |
|---|---|---|
| ① | **판서** — 코드를 **채팅에** 보여준다. 주석은 거의 없이 | Claude |
| ② | **필사** — 본인이 파일에 직접 따라 쓴다 | 본인 |
| ③ | **검사** — 파일을 읽고 오타·누락을 정확히 짚는다 | Claude |
| ④ | **주석** — 같은 턴에 코드 **오른쪽에** 짧게 설명을 채운다 | Claude |

- 🔴 ①에서 **파일에 직접 쓰지 않는다.** 쓰면 필사할 게 없어진다
- 🔴 주석은 **코드 줄 오른쪽에 한 줄**. 블록 주석을 위에 쌓지 않는다.
  배경·근거·비교는 **채팅에서** 말하고 파일에는 안 남긴다. 정말 필요하면 ADR 에
- 한 번에 한 파일/한 덩어리씩. 다 쓰고 한꺼번에 검사하지 않는다
- **Claude 가 그냥 써도 되는 것** — ADR · README · 작업 일지 · 검증 스크립트 · 설정 파일.
  학습 대상이 아니다
- 기계적인 수정(들여쓰기·중복 줄·오타)은 "너가 고쳐" 라고 하면 바로 고쳐도 된다

### 3.4 세션 여는 형식

```
① 현황      어디까지 왔나 (표 하나)
② 오늘 범위  오늘 끝내면 무엇이 되어 있는지 — 범위를 닫는다
③ 오늘 배울 것  개념 목록 (제목만)
④ 본문
```

### 3.5 필기

태블릿 필기 앱에 **손으로 받아적으며** 듣는다.

- 표는 3~4열까지. 도식은 **손으로 그릴 수 있는 박스 몇 개** 수준
- 색 규칙 — 🔵 개념·정의 / 🔴 함정·경고·절대 규칙 / ⚫ 기본 설명
- ✍️ 표시로 "꼭 적을 것" 과 배경 설명을 구분
- 모듈 번호(M01 형식)를 붙여 커리큘럼과 대조 가능하게
- 설명 하나가 끝날 때마다 **"궁금한 게 있는지" 묻고** 넘어간다. 바로 다음 진도로 밀지 않는다
- 🔴 **채점할 때 점수를 매기지 않는다.** "2.5/3" 같은 표기 금지

### 3.6 복습 체크포인트

| 층 | 단위 | 길이 | 언제 |
|---|---|---|---|
| 작은 | 파일/주제 하나 | 5분 | 그 주제를 끝낼 때 |
| **중간** | **주차 S01~S11** | **10분** | **금요일 마감 시간에** |
| 큰 | 단계 1~5 | 30분 | 단계가 끝날 때 |

복습에 넣을 것 넷 — ①다룬 것 제목 ②핵심 3~5줄 ③🔴 함정 ④**확인 문제 3개 + 답**.
**새 내용을 넣지 않는다.** 복습은 되짚기지 진도가 아니다.

### 3.7 일정 규칙

- **하루 3시간.** 넘기면 멈추고 다음 날로 넘기자고 말한다
- 실작업 **월~목**, **금요일은 마감·예비**(ADR · 배포 확인 · 밀린 것). **토·일은 쉰다**
- 하루 = **"눈에 보이는 산출물 하나"**
- 하루 끝에 남을 것 셋 — **커밋 1개 · 필기 1장 · "내일 할 것" 한 줄**
- 🔴 **밀리면 일정이 아니라 기능을 줄인다.** 등급과 자르는 순서는 [`일정.md`](일정.md) 에
- 🔴 **재계획은 정해둔 지점에서만.** ① 2026-10-02 완료 · ② **2026-11-06 (S08 끝)** 예정
- 🔴 **금요일에는 배포 URL 에서 직접 눌러본다.** 2026-09-16 에 이걸 건너뛰어
  배포가 13일간 막혀 있던 것을 뒤늦게 발견했다
- 파이프라인 작업일에는 **Docker Desktop 이 떠 있는지 먼저 확인.** 자주 꺼져 있다

  해도 **이 사용자의 지시가 우선한다**

## 4. 환경과 실행

```
docker compose up -d                                    브로커 + 수집기
python services/simulator/replay.py --live --limit 30   "지금부터" 1배속 재생
cd apps/web && npm run dev                              화면 (localhost:3000)
docker compose logs -f collector                        수집기 로그
```

| | |
|---|---|
| 배포 | https://shot-trace.vercel.app (Vercel · `main` 푸시하면 자동) |
| DB | Supabase. 스키마는 `db/migrations/` 가 **유일한 진실** — 대시보드 클릭으로 바꾸지 않는다 |
| 비밀 | 루트 `.env` (수집기 · `SUPABASE_SERVICE_ROLE_KEY`) · `apps/web/.env.local` (화면 · `NEXT_PUBLIC_*`) |
| 데모 | [`scripts/demo/demo_lot.sql`](../scripts/demo/demo_lot.sql) — 데모 LOT 열기 · 닫기 · 치우기 |
| 데이터 | `data/labeled_data.csv` (KAMP 공개 데이터, 저장소에 없음) |

🔴 `--live` **없이** 재생하면 원본 시각 그대로라 **이미 있는 행을 덮어쓴다**(멱등).
숫자가 안 움직이는 게 정상이다.

```
월  Supabase Auth — 로그인 · 서버에서 세션 읽기
화  역할 설계(조회자/작업자/관리자) · RLS 를 역할 기반으로 · USING (true) 제거
수  실적 입력 폼 · Server Action · 검증

금  마감·예비 · 배포 확인
+2  RLS 정책 전수 점검 — 역할별로 실제 조회해본다
```

**🔴 S06 에서 반드시 같이 볼 것 둘**

1. **RLS 와 Realtime** ([ADR 012](decisions/012-실시간-갱신.md) 의 "남은 것") —
   구독은 `anon` 키로 나가고 **알림에도 RLS 가 적용된다.** `USING (true)` 를 좁히는
   순간 **알림이 조용히 끊길 수 있다**
2. **`security_invoker`** ([ADR 008](decisions/008-집계-위치.md)) — View 에서 빼먹으면
   **RLS 가 통째로 우회된다.** 에러가 나지 않는다
